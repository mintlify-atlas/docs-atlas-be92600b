## Data flow

The two products communicate bidirectionally. The CRM holds the source-of-truth for wedding and lead data; the RSVP Platform holds the source-of-truth for guest RSVP status.

| Direction       | Mechanism                                                                 |
| --------------- | ------------------------------------------------------------------------- |
| CRM → RSVP      | Push guest lists via `POST /api/crm/weddings/:id/guests/sync`             |
| CRM → RSVP      | Pull headcounts via `GET /api/crm/weddings/:id/headcounts`                |
| CRM → RSVP      | Pull guest list via `GET /api/crm/weddings/:id/guests`                    |
| CRM → RSVP      | Register webhook URL via `PUT /api/crm/weddings/:id/webhook`              |
| RSVP → CRM      | Real-time webhooks fired on every RSVP submission; CRM caches locally     |

## Integration flows

There are five distinct flows that make up the CRM ↔ RSVP integration:

**1. Setup**

In the CRM, open any wedding → **RSVP & Guests** tab → **Connect RSVP Platform**. Enter the RSVP Platform URL, Wedding ID, and Planner API Key, then save.

**2. Auto webhook registration**

When integration settings are saved, the CRM automatically calls `PUT /api/crm/weddings/:id/webhook` on the RSVP Platform to register its inbound webhook URL (`http://localhost:3001/api/webhooks/rsvp`). No manual configuration is required.

**3. Data pull (CRM → RSVP)**

The CRM proxies read requests through its own API layer to the RSVP Platform:

- `GET /api/weddings/:id/rsvp/headcounts` → proxies to RSVP's `/api/crm/weddings/:id/headcounts`
- `GET /api/weddings/:id/rsvp/guests` → proxies to RSVP's `/api/crm/weddings/:id/guests`

If the RSVP Platform is unreachable, responses fall back to the locally cached `RSVPGuest` records in the CRM database.

**4. Data push (CRM → RSVP)**

The CRM can push its guest list to the RSVP Platform:

- `POST /api/weddings/:id/rsvp/sync` → proxies to RSVP's `/api/crm/weddings/:id/guests/sync`

Guests are deduplicated by phone number on the RSVP side.

**5. Real-time updates (RSVP → CRM)**

When a guest submits an RSVP on the RSVP Platform, `dispatchRSVPWebhook()` fires a fire-and-forget POST (5 s timeout) to the CRM's webhook receiver at `/api/webhooks/rsvp`. The CRM upserts the `RSVPGuest` cache record immediately. If the CRM is offline, a full resync via `POST /api/weddings/:id/rsvp/full-sync` rebuilds the local cache from scratch.

## Authentication

| Direction             | Mechanism                                                                 |
| --------------------- | ------------------------------------------------------------------------- |
| CRM → RSVP API calls  | Bearer token (`Planner.apiKey`) in the `Authorization` header             |
| RSVP → CRM webhooks   | No auth in development (localhost); HMAC signing recommended for production |
| Guest RSVP portal     | Unique token in the URL path (`/guest/:guestToken`)                       |
| Event-day check-in    | PIN per event + HMAC-SHA256-signed QR codes                               |
